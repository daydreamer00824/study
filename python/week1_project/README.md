AI错误总结:
你第一周的错误，归根到底不是“不会写语法”，而是这 5 类问题。

第一类是参数、类型、路径没有对齐。
你一开始最典型的问题是：函数希望接收 Path，但你传进去的是字符串；或者某些参数不是必填，但后面你又默认它一定存在。比如 config、logs 没设成必填，却在后面直接拿来构造路径。这类错误的本质是：你没有在写代码时持续检查“这个变量现在到底是什么类型、有没有值、能不能直接用”。这是第一周你最重要的短板之一。

第二类是返回值不稳定。
你有些函数在正常情况下返回一个值，异常情况下又直接 return，结果返回的是 None；但主函数后面却还把它当列表或者两个值来用。比如收集文件的函数，前面主流程期待它返回两个值，你某一版里却只返回了一个空列表。这类错误的本质是：函数的输入输出契约没有想清楚。以后你要养成一个习惯——一个函数应该稳定地返回什么，必须从头到尾一致。

第三类是把“对象存在”和“路径存在”混淆了。
你之前写过 if not input_dir: 这样的判断，想检查目录是否存在。但 input_dir 作为一个 Path 对象，本身已经存在于内存里了，这不等于磁盘上的目录存在。所以后来你改成了 exists() 和 is_dir()，这才是对的。这个错误说明你一开始对“变量本身”和“变量代表的外部资源”还没有分清。

第四类是数据结构和语法细节不够严谨。
这一类问题在你第一周最明显，比如列表推导式写错、join() 的用法错、列表和字符串的拼接逻辑不清楚。像你当时写 lines2 = [str(file_name.name), str(file_name.suffix) for file_name in file]，本质不是思路错，而是语法结构没有搞明白。还有 "\n".join(lines, lines2) 这种写法，也是因为你还没有真正掌握“一个函数到底接收什么参数”。这类问题的本质是：你会模仿，但对 Python 容器和函数接口的理解还不够稳。

第五类是工程意识刚建立，但还没有完全形成闭环。
这其实是你第一周最关键的阶段特征。你已经知道要分函数、要写日志、要读配置、要生成报告，这是很好的开始；但你当时还做不到让每一层逻辑都严丝合缝地接上。比如日志函数没有返回值，你却接了一个变量；报告函数里想保存更多信息，但组织方式比较乱；配置文件读取做了异常处理，但主流程一开始还没有完全收住。这说明你已经从“乱写脚本”进步到了“开始写工程”，只是工程细节还没收紧。

如果我把你第一周的错误再压缩成一句话，那就是：

你第一周最大的错误，不是知识点不会，而是代码各部分之间的连接关系还不够稳。

也就是说，你的问题主要不是单点知识，而是：

变量能不能直接用
函数到底返回什么
这个判断检查的是对象本身还是文件系统
这一层出错后下一层会怎样
这个数据结构是不是和函数接口匹配

这恰好是第一周最该暴露、也最该改掉的问题。

我再给你一个更适合记忆的“第一周错误清单”，你以后写代码前可以自己对照：

参数是不是一定存在。
传进去的是不是正确类型。
路径检查是不是用了 exists() / is_dir()。

列表、字符串、路径拼接是不是符合函数接口。
出错时程序会不会直接崩。
