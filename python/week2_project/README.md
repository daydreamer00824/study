部署前简单的图像预处理（工程化）：
AI错误总结:
第二周你最核心的错误，第一类是对文件系统和输出路径的理解还不够扎实。
最典型的例子，就是你一开始把 cv2.imwrite() 的参数直接写成了输出目录，而不是完整的输出文件路径。这个错误非常有代表性，因为它说明你已经知道“要保存结果”，但还没有完全建立“文件”和“目录”是两种不同对象的意识。工程里这种问题很常见：你知道要写输出，但没把输出路径真正设计完整。后来你改成 output_dir / file_name.name，这就对了。

第二类是图像读取成功与否的检查意识不够早建立。
你第二周早期代码里，一开始是直接对 img.shape、img.dtype 做日志输出，默认 cv2.imread() 一定成功。但实际上 OpenCV 读图失败时会返回 None，不是直接抛异常。如果不先判断 img is None，后面访问 shape 就会直接报错。这个错误的本质是：你已经开始处理真实数据了，但还没有把“输入可能失败”当成默认前提。后来你把 img is None 的判断补上了，这是第二周一个很重要的进步。

第三类是数据维度的理解开始有了，但 batch 维度的处理还不够牢。
这是第二周最有技术含量、也最值得你重视的一类错误。你已经正确做出了：

HWC -> CHW
expand_dims(axis=0)

这说明你开始理解模型输入格式了。
但你后面又把这些 (1, C, H, W) 的数组放进列表，再用 np.stack(..., axis=0)，结果会得到 (N, 1, C, H, W)，比你真正想要的多了一维。这个错误的本质不是“不会 NumPy”，而是你刚开始进入“多维数组思维”，对每一步加维、拼接、堆叠后的最终 shape 还不够敏感。第二周最大的成长点，其实就在这里：你开始不只是写代码，而是开始学会“脑子里先预判 shape 会变成什么”。

第四类是输出数据存在“空列表风险”时，没有先兜底。
比如你后来要把预处理后的图像保存成 .npy，这是非常好的思路，说明你已经开始往“张量数据落盘”去想了。但当时你直接对 imglist 做 np.stack()，没有先判断它是不是空的。如果一个有效图片都没有，就会直接报错。这类错误的本质是：你开始做批量处理了，但对“零样本场景”还不够敏感。工程代码里，空输入、空结果、空目录、空配置，都是必须主动考虑的。

第五类是日志使用比第一周进步了，但“错误”“警告”“正常跳过”之间还没有完全区分开。
你第二周有一版会把“不是图片”的文件也记成 warning，甚至更早的时候有些本来只是普通分支，也被你记成像错误一样的日志。这说明你已经有日志意识了，但还没有完全掌握：什么情况是真错误，什么情况只是正常过滤，什么情况需要 warning。工程里日志不是越多越好，而是越准确越好。这个能力你已经开始建立了，但第二周还在形成中。

第六类是你开始有结果闭环意识，但闭环还不完整。
这是第二周和第一周最大的区别。第一周你更多是在搭骨架；第二周你已经开始想：

预处理后要不要保存预览图
张量要不要保存成 .npy
要不要记录 shape 和 dtype
要不要生成文本报告

这说明你已经从“能处理图片”进步到了“想验证处理结果”。这是非常重要的进步。
但你一开始的闭环还不够完整，比如：

预览图保存路径不对
.npy 的 shape 不一定是你想要的
输出目录未必提前存在
空列表时保存会失败

所以第二周的主要问题，不是“没想到输出”，而是“输出想到了，但还没完全收口”。

如果把你第二周的错误压缩成一句话，就是：

你第二周最大的错误，不是不会图像处理，而是对“图像处理后的数据、文件和 shape 会变成什么”还没有形成完全稳定的控制。

这是一种很典型、也很正常的第二周状态。因为你已经从“只会写逻辑”进入到了“开始管理数据流和结果流”的阶段。

我再给你一个适合以后自检的“第二周错误清单”，你每次写图像处理代码前都可以先过一遍：

图片读进来后有没有先判断 img is None。
现在这一步处理后的 shape 是多少。
这一步处理后的 dtype 是多少。
当前数组是 HWC 还是 CHW。
是不是已经多加了一层 batch 维。
保存结果时给的是目录还是完整文件路径。
输出目录有没有提前创建。
空列表、空结果时会不会报错。
日志里 warning 和 error 有没有乱用。
最终保存出来的预览图、报告、.npy 是否真的能验证你的处理结果。

如果再进一步总结你的第二周成长轨迹，其实是这样的：

第一周你在学“程序怎么搭起来”
第二周你在学“图像数据怎么流动起来”
第二周犯的错，已经不是初学者乱写脚本那种错了，而是进入图像工程阶段后很常见的“shape、路径、输出、边界条件”问题

这说明你是在往前走的，而且走得是对的。
